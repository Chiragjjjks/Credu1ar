Credu1ar v0.1.3 reads your **bank statement**. Add the PDF your bank emails you, and the app shows where the money went: one bar per category, your top places, and what was only moved between accounts. It reads every row and checks them against the closing balance. This release also has a **statement-only edition** that never asks for SMS, so it installs straight from the browser.

## What's new

- **Add bank statement.** It's at the top of **Arm it**, on an empty Pulse, and in **System → Bank statements**.
  - Pick one or more PDFs with Android's own file picker.
  - A locked PDF asks for its password once and never saves it.
  - The file is read on the phone and never copied or sent.
  - **Kotak savings statements only so far**: the monthly one Kotak emails (16th → 16th), or any date range from net banking.
- **Proof that nothing was missed.** After reading, you see `202 ROWS · ADDS UP TO THE CLOSING BALANCE ✓`. This means every row's amount matches its change in balance, the row numbers run without gaps, the opening and closing balances match the bank's summary, and no page is missing. If a row doesn't add up, it is left out and you're told.
- **A simple report on Pulse.** Switch between `BY STATEMENT · BY MONTH`.
  - "You spent ₹X from 16 Sep to 16 Oct", then Money in · Payments · Per day.
  - **Where it went:** one bar per category, biggest first. Payments the app could only guess at sit in an amber **Not sorted yet** bar instead of inflating a category.
  - **Top places**, and **Not spending** (card bills, your own accounts, investments).
  - Tap a bar to see its payments and fix any of them.
- **Several months, honestly.** A month that statements only partly cover says so ("from 1 to 16 October · 16 of 31 days") and is never compared with another month. Add the next statement and the month fills in.
  - Adding the same statement again, or two statements that overlap, never counts a payment twice.
  - A payment already captured from SMS and also on the statement becomes one row.
- **Sorting at scale.** Needs a look lists the biggest payees first. **Mark these N as people** files every payee that looks like a person in one tap; any one can be changed later.
- **Better names for statement payees.**
  - Cut-off names are recognised: "BANGALORE METR" → Namma Metro, "Zomato Media P" → Zomato, "Sri Lakshmi Stor" → a provision store.
  - New categories: **Bank charges & fees** and **Interest**.
  - A transfer to your own name is marked as an own-account transfer for you to confirm.
- **Your name and account number are not stored.** The statement header (name, address, account number, IFSC) is read in memory only. Only the last 4 digits of the account are kept, and your printed name is removed from every narration.

## Two APKs

- **`Credu1ar-v0.1.3-statement.apk`**: statements only. It never asks for SMS or notification access, so Play Protect's SMS block doesn't apply and it installs from the browser. It simply cannot read SMS.
- **`Credu1ar-v0.1.3-android.apk`**: the full app (SMS + notifications + statements). Play Protect still blocks browser installs of this one in India; install it from a computer (`scripts/phone-install.sh`). See [docs/INSTALL.md](https://github.com/Chiragjjjks/Credu1ar/blob/main/docs/INSTALL.md).

Verify either download against `SHA256SUMS.txt` on this page.

## Measured (local gate on this Mac, Android 15 emulators, JDK 17)

- **Tests:** **73** JVM tests, 0 failures. That includes 2 fictional Kotak statements (35 + 8 rows) checked row by row, plus own-name matching, SMS matching, coverage and report tests. Lint: 0 errors on both editions.
- **Emulator smoke tests:** PASS for both editions, through Android's real PDF reader.
  - Locked PDF (wrong, then right password): 35 rows. Same file again: +0. Overlapping next statement: 41 in total.
  - SMS then statement, and statement then SMS: one row either way.
  - Removing a statement keeps rows another statement covers.
  - A row that doesn't add up is left out.
  - The SMS smoke test still passes.
- **The owner's real Kotak statement:**
  - **Reading:** every row was read and the statement is complete. Totals equal the bank's own opening and closing balances.
  - **Sorting:** most of the money went to payees that look like people, or that couldn't be placed. They start in Not sorted yet; one tap files the people.
  - **Privacy:** the file was read on a local emulator and then wiped; none of its contents are in this repo.
- **Database upgrade:** a v0.1.2 install with 237 rows was upgraded to the new database with every row and rule intact.
- **Size:** the full release APK is 1,469,416 bytes; the statement edition is 1,452,088 bytes, both R8-minified. The PDF reader is Android's own, so it adds nothing.

## Not verified yet

- **A real phone.** Android 15+ reads PDFs with its built-in reader; Android 11–14 needs current Google Play system updates. Real statements from other Kotak account types are untested.
- Large statements (a year, thousands of rows) are not timed.

## Known limits

- **Kotak only.** Statements from other banks are recognised as "can't read this layout yet". The next bank needs a sample (made fictional before it enters the repo).
- **Statement rows have no time of day.** They show the date only and stay out of the time-of-day heatmap.
- **Signing:** GitHub Actions builds these releases without the project's signing secrets, so each release has a new throwaway key. Uninstall before installing a newer one until the owner runs `scripts/set-signing-secrets.sh`. The full and statement editions don't share data.
