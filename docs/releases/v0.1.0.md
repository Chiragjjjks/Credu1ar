Credu1ar v0.1.0 is the first build: it reads your payment SMS and notifications on the phone and shows where the money went. Everything stays on the phone.

## Install

1. Download `Credu1ar-v0.1.0-android.apk` and open it. Android 8 or newer. Verify it against `SHA256SUMS.txt` if you like.
2. Open the app and follow **Arm it**. On Android 13+ the system blocks SMS and notification access for apps installed outside a store until you do this once: **Settings → Apps → Credu1ar → ⋮ → Allow restricted settings**, then grant SMS and Notification access.
3. Optional: **Import last 90 days** to read bank alerts already in your inbox.

## What's new

- **Capture:** payment SMS (manifest receiver, no always-on service), Google Messages RCS and UPI-app alerts (notification listener, allow-listed apps only), and a catch-up scan of the inbox so nothing is lost if the phone froze the app.
- **Understanding:** parser for HDFC, ICICI, SBI, Axis, Kotak, PNB, IDFC and generic UPI/card/ATM/NEFT/IMPS styles. OTPs, promos, failed payments, balances and "will be debited" notices are dropped unread. Duplicates between SMS and notifications are merged.
- **Categories:** two levels, with groceries split into quick commerce / provision store / supermarket / fresh & dairy, and food delivery separate from dining out. Credit-card bill payments and investments never count as spending.
- **Learning:** unsure payees are grouped in **Needs a look**. One tap files every payment to that payee, and it remembers.
- **Screens:** Pulse (spend, pace, category ring), Ledger (search and filters), Insights (day-by-day, leaks, movers, recurring, rhythm), System (live capture status, traffic counters, privacy switches, CSV export, masked diagnostics report).
- **Privacy:** no account, no server, no analytics, no cloud backup. The only network call is the update check you start yourself.

## Numbers (measured on an Android 15 emulator, release build)

- APK: **1.32 MB**, signed, R8-minified.
- Foreground memory with sample data loaded: ~38 MB PSS.
- Tests: 26 JVM tests (parser fixtures, categoriser, insights, de-dup, money) and an emulator smoke test (real multi-part SMS PDU → stored → de-duplicated → OTP dropped).

## Not verified yet

- **A real phone.** The restricted-settings flow, Google Messages RCS capture and phone-maker battery behaviour have only been reasoned about, not run. Use `docs/PHONE-TEST.md` and the System → Diagnostics report.
- **Real bank formats.** Fixtures are synthetic, modelled on public SMS styles. Messages the parser cannot read appear under System → Couldn't read (digits masked) so a new rule can be added.
- Idle battery and RAM cost when the app is closed have not been measured.

## Known limits

- INR only; foreign-currency card spends are listed as unreadable.
- Notification text can be truncated by the sending app; the SMS version wins when both exist.
- **Signing:** this release was built by GitHub Actions without the project's signing secrets, so it is signed with a throwaway key generated on the build machine. It installs and runs normally, but a later release signed with the real key cannot be installed over it: you would uninstall first. Your history is not lost for good: after reinstalling, **System → Import SMS history** rebuilds the ledger from the bank messages still in your inbox (corrections you taught the app would need teaching again; **System → Export → CSV** before uninstalling keeps everything). Once the owner adds the signing secrets, releases are signed with the private key and update in place.
- Released as a preview to follow the full release cycle; not yet tried on a real phone.
